<h2 id="big-o">Big-O</h2>

<code>Junior</code> · <code>Часто</code>

<details>
<summary><strong>Показать ответ и Swift</strong></summary>

Big-O это как цена алгоритма растёт с размером входа: время или лишняя память, worst case, если не сказал иначе. На iOS-собесе ждут бытовые вещи: индекс массива O(1), contains по массиву O(n), lookup в Set / Dictionary в среднем O(1), сортировка O(n log n), вложенные циклы O(n²). Это не «функция тормозит на моём телефоне». Хеш-таблица всё ещё может быть O(n), если хеш плохой. Типичный промах: filter плюс contains в цикле и сказать, что код O(n). У Dictionary среднее O(1), worst при вырождении O(n). String.count в Swift это O(1) для String, не путать с ручным проходом по Character. Set на n элементов ест O(n) памяти.



```swift
func hasOverlap(_ ids: [Int]) -> Bool {
    var seen = Set<Int>()          // lookup O(1) average
    for id in ids {                // n
        if seen.contains(id) { return true }
        seen.insert(id)
    }
    return false
}
```

- Пространственная сложность подхода с Set?

<h2 id="recursion">Рекурсия</h2>

<code>Junior</code> · <code>Средне</code>

<details>
<summary><strong>Показать ответ и Swift</strong></summary>

```swift

    guard let node else { return 0 }
    return 1 + max(depth(node.left), depth(node.right))
}
```

<h2 id="circular-buffer">Circular buffer</h2>

<code>Mid</code> · <code>Средне</code>

<details>
<summary><strong>Показать ответ и Swift</strong></summary>

Ring buffer это фиксированный массив плюс head и count, или head и tail. Запись двигает хвост, чтение двигает голову, оба заворачиваются через % capacity. Когда полон, либо выкидываешь самое старое (аудио, телеметрия), либо отказываешь в записи. Никакого remove(at: 0) у Array, это O(n). История на собесе: очередь аудио или сенсора в реальном времени, которая не должна аллоцировать под нагрузкой. Типичный промах: off-by-one при count == capacity или забыть wrap и затереть непрочитанные сэмплы. На колбэке микрофона обычно drop-oldest, бэкпрешер там опоздает. Push/pop между двумя потоками закрываю одним lock или однопродюсер/одноконсьюмер без лока. Array плюс removeFirst на 48 kHz это O(n) на каждый поп и под нагрузкой не живёт.



```swift
struct RingBuffer<T> {
    private var slots: [T?]
    private var head = 0
    private var count = 0

    init(capacity: Int) { slots = .init(repeating: nil, count: max(1, capacity)) }

    mutating func push(_ value: T) {
        let i = (head + count) % slots.count
        if count == slots.count { head = (head + 1) % slots.count }
        else { count += 1 }
        slots[i] = value
    }

    mutating func pop() -> T? {
        guard count > 0 else { return nil }
        defer { slots[head] = nil; head = (head + 1) % slots.count; count -= 1 }
        return slots[head]
    }
}
```

<h2 id="sorted-list-dups">Убрать дубли из отсортированного списка</h2>

<code>Mid</code> · <code>Средне</code> · <code>Practice</code>

<details>
<summary><strong>Показать формулировку</strong></summary>

Дан head отсортированного односвязного списка. Удали дубли, чтобы каждое значение встретилось один раз. Идёшь указателем current: если current.val == current.next.val, пропускаешь следующий узел, иначе шагаешь. <h2 id="linked-list-cycle">Цикл в связном списке</h2>

<details>
<summary><strong>Показать формулировку</strong></summary>

Определи, есть ли цикл в односвязном списке. Проговори Floyd: slow +1, fast +2, встречаются тогда и только тогда, когда цикл есть. Упомяни ответ через Set узлов за O(n) и почему хотят O(1) доп. памяти. Найти начало цикла это follow-up: один указатель на голову, идут вместе.
